# ThermoLift – CSS + SRP Well-to-Surface Digital Twin (Baghewala prototype)

Hybrid **physics + ML** twin: reservoir heat decay → viscosity → inflow → rod-fall velocity → SRP loading, with ML models
trained on well/cycle/daily data and two optimizers (CSS recipe, SRP set-points).

## Run
    pip install -r requirements.txt
    cd src && python make_data.py && python train.py && cd ..   # optional: models/ and data/ are pre-built
    streamlit run app.py

## Layout
| file | role |
|---|---|
| src/physics.py | thermal / viscosity / rod-float / power / economics model (from the ThermoLift design) |
| src/make_data.py | generates 120 wells, 597 CSS cycles, 43k well-days with sensor noise and failure events |
| src/train.py | trains 6 models, cross-validated **by well**; writes models/metrics.json |
| src/optimizer.py | `css_optimize` (steam vol × soak × pressure, profit-rate cut-off) and `srp_optimize` (safe SPM / VFD duty) |
| src/kaggle_adapter.py | maps a real/Kaggle CSV into the training schema |
| app.py | Streamlit dashboard: Twin, CSS Advisor, SRP Advisor, Model performance |

## Data caveat (important)
The training data is **synthetic**, generated by the physics engine – Kaggle was not reachable when this was built and Baghewala
data is proprietary. So ML scores show the pipeline works, **not** field accuracy. To go real: export Oil India CSS/SRP/VFD/failure
history to `data/cycles.csv` + `data/daily.csv` (same columns), or run `kaggle_adapter.py` on a public set (e.g. Volve), then `python train.py`.
Physics constants (Kfall, tauBase, viscosity curve) should be calibrated to Baghewala lab/field data.
